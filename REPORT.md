# Отчёт по проекту

## 1. Назначение

Приложение предназначено для хранения и подготовки задач по программированию к использованию в контестах. Для задачи хранятся название, условие, идея решения, Polygon URL, признаки готовности для Codeforces и Yandex Contest, сложность, теги, контесты и примечание.

## 2. Архитектура

Решение разделено на слои:

- Domain — сущности и правила предметной области;
- Application — поиск, фильтрация и прикладные операции;
- Infrastructure — SQLite, репозитории, авторизация и справочники;
- Wpf — пользовательский интерфейс;
- Tests — автоматические тесты.

## 3. База данных

Используется SQLite. Основные таблицы: `ProgrammingTasks`, `Tags`, `Contests`, `TaskTags`, `TaskContests`, `Users`. Связи задач с тегами и контестами реализованы отношениями многие-ко-многим.

## 4. Права доступа

`root` имеет полный доступ к задачам, справочникам и пользователям. `user1` и созданные менеджеры просматривают, фильтруют и экспортируют данные. Административные элементы скрываются для обычной роли.

## 5. Тестирование

Проверяются фильтрация по сложности и тегам, автозаполнение признака Codeforces, проверка диапазона сложности и авторизация пользователей.

## 6. Развёртывание

Для автономной сборки используется `publish.ps1`. Скрипт создаёт self-contained версию `win-x64` в папке `publish`; установка .NET на демонстрационном компьютере не требуется.

## 7. Скриншоты

Добавить скриншоты окна входа, списка задач, фильтрации, формы администратора, справочников и отчёта после записи демонстрации.

## 8. Принцип работы программы

При запуске WPF-приложение открывает окно авторизации. `AuthenticationService` подключается к SQLite, создаёт таблицу пользователей и проверяет логин. После успешного входа приложение создаёт главное окно и передаёт ему сведения о роли пользователя.

`SqliteTaskRepository` создаёт таблицы задач, тегов, контестов и связей между ними. Если база пуста, выполняется начальное заполнение демонстрационными записями. Данные отображаются в таблице главного окна.

При применении фильтра введённый диапазон сложности разбирается методом `ParseDifficultyRange`, а список тегов передаётся в `TaskService.Search`. Сервис оставляет только задачи, которые попадают в диапазон и содержат все выбранные теги.

Администратор открывает формы CRUD. При сохранении `TaskService.Save` проверяет название и сложность, а `TaskRules.IsPreparedForCodeforces` автоматически вычисляет признак готовности по Polygon URL. Репозиторий сохраняет задачу и её связи с тегами и контестами.

При двойном щелчке открывается окно подробностей. Отчёт строится по текущей выборке, а CSV формируется в `MainWindow.ExportClick`.

## 9. Логирование

`ApplicationLogger` находится в проекте `ProgrammingTasks.Infrastructure`. Лог записывается в `logs/application.log` рядом с исполняемым файлом. Каждая запись содержит время, уровень и этап: запуск, авторизация, SQLite, загрузка данных, CRUD и исключения. Это позволяет определить место сбоя даже в опубликованной версии.

## 10. Ключевые методы

- `AuthenticationService.Authenticate` — проверка пользователя;
- `SqliteTaskRepository.GetAll` — чтение задач и связей;
- `SqliteTaskRepository.Save` — создание или изменение задачи;
- `TaskService.Search` — фильтрация;
- `TaskRules.ValidateDifficulty` — проверка сложности;
- `TaskRules.IsPreparedForCodeforces` — вычисление статуса Codeforces;
- `UserManagementService.AddManager/Delete` — управление пользователями;
- `CatalogService.AddTag/AddContest` — управление справочниками.

## 11. Как пользоваться программой по назначению

1. Войти как `user1` для просмотра или как `root` для редактирования.
2. В обычной работе найти задачу через поле диапазона сложности, например `3–7`, и поле тегов, например `Графы, Динамическое программирование`.
3. Нажать «Применить», чтобы получить подходящие задачи.
4. Дважды щёлкнуть задачу, чтобы прочитать условие и идею решения.
5. Использовать Polygon URL для перехода к подготовке задачи к загрузке в систему проверки.
6. Нажать «Отчёт» для статистики текущей выборки или «CSV» для сохранения отчёта.
7. Администратору доступны добавление и редактирование задач, справочники тегов и контестов, а также менеджеры пользователей.

## 12. Направленность автоматических тестов

Тесты проверяют не внешний вид, а критически важные правила программы: фильтрацию по диапазону сложности и нескольким тегам, автоматическую установку признака Codeforces при наличии Polygon URL, запрет сложности вне диапазона 1–10, вход пользователя без пароля и отклонение неправильного пароля администратора. Это защищает основные сценарии от случайных поломок при изменении кода.

## 13. Подключение PostgreSQL

По умолчанию приложение работает с локальной SQLite-базой, потому что она не требует установки сервера и удобна для первого запуска. Администратор может открыть раздел подключения PostgreSQL и указать сервер, порт, имя базы, логин и пароль. Начальные значения: `localhost`, `5432`, `programming_tasks`, `postgres`, `postgres`.

После успешной проверки соединения приложение создаёт таблицу PostgreSQL, переносит туда задачи из SQLite и переключает операции приложения на PostgreSQL. Настройки сохраняются в `postgres-connection.json` и снова доступны в форме подключения.

Для удалённого сервера PostgreSQL администратор сервера должен создать базу и пользователя, разрешить подключения в `postgresql.conf`, добавить адрес клиента в `pg_hba.conf`, открыть порт 5432 в сетевом экране и убедиться, что сервер доступен по сети. Пароль не следует передавать в отчёте или хранить в репозитории.

| Характеристика | SQLite | PostgreSQL |
|---|---|---|
| Тип | Файл базы данных | Серверная СУБД |
| Установка сервера | Не требуется | Требуется PostgreSQL на сервере |
| Режим работы | Локальный запуск по умолчанию | Подключение по адресу и порту |
| Переносимость | Один файл | Сервер, база, пользователь и права |
| Назначение в проекте | Демонстрация и автономный запуск | Централизованное хранилище |
| Изменение данных | Приложение | Только через приложение |
